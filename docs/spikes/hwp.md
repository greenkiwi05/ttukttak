# HWP → PDF 스파이크 (2026-11-15)

## 결론
**아직 페이지로 만들지 않는다 (`hwp-to-pdf`는 planned 유지).**
후보 라이브러리가 하나 생겼지만, 실제 HWP 파일로 브라우저에서 품질을 확인하기 전에는
"HWP PDF 변환"이라는 이름으로 공개하기 어렵다. 깨진 결과는 AdSense·검색 신뢰도에 오히려 손해다.

## 후보 조사

| 패키지 | 상태 | 라이선스 | 메모 |
|---|---|---|---|
| `@ohah/hwpjs` 0.1.1 | 2026-11-08 공개, 활발히 개발 중 | MIT | HWP5·HWPX 모두 읽기. Zig→WASM 엔진 + Worker. 브라우저에서 `createCanvasSurface`로 Canvas 렌더링. README가 "서식·개체·조판 완전 재현은 지원 예정", "HTML 내보내기는 원본 서식·페이지 배치 동등성 보장 안 함"이라고 직접 밝힘 |
| `hwp.js` 0.0.3 | 2022-05 이후 갱신 없음 | Apache-2.0 | HWP5 뷰어. 사실상 중단 |

### `@ohah/hwpjs` 쓸 때 고려할 점
- 패키지 크기 약 13.9MB(압축 해제). `dist/worker.js`, `dist/hwpjs.wasm`을 `public/hwpjs/`로 복사해 정적 자산으로 배포해야 함
  → 이 페이지에서만 동적 로드하면 원칙 5(가볍게)는 지킬 수 있음. Cloudflare Pages 단일 파일 25MB 제한 확인 필요
- 0.1.1은 공개된 지 2주가 안 됨. 실제 도입 시 버전을 정확히 고정하고, 올리기 전에 직접 확인
- PDF 저장은 Canvas 렌더링 결과를 `window.print()`로 인쇄하는 방식이 현실적 (TOOLS.md 2단계 계획과 같음)

## 다음 단계 (사람이 확인할 일)
1. 실제로 자주 쓰는 HWP 파일 몇 개 준비: 공문서 양식, 표가 많은 문서, 이미지가 들어간 문서, HWPX
2. 데모(https://ohah.github.io/hwpjs/editor/demo/vanilla/)에서 열어 보고 표·이미지·쪽 나눔이 쓸 만한지 판단
3. 쓸 만하면 → "HWP 뷰어 (설치 없이 열기)"로 먼저 공개하고, 인쇄로 PDF 저장 안내
   쓸 만하지 않으면 → HWPX(ZIP+XML)만 텍스트 미리보기로 축소하거나 보류
